# Legal pages API requirements

The frontend expects two fixed slugs: `privacy-policy` and `terms-and-conditions`.

## Public endpoint

`GET /api/v1/content/legal-pages/:slug`

## Admin endpoints

`GET /api/v1/admin/content/legal-pages/:slug`

`PATCH /api/v1/admin/content/legal-pages/:slug`

The admin endpoints require a valid admin bearer token. The PATCH JSON body is:

```json
{ "title": "سياسة الخصوصية", "content": "..." }
```

All successful responses use this shape:

```json
{
  "success": true,
  "data": {
    "slug": "privacy-policy",
    "title": "سياسة الخصوصية",
    "content": "...",
    "updatedAt": "2026-08-23T12:00:00.000Z"
  }
}
```

Content is stored and returned as sanitized HTML generated by the rich-text editor. The backend must sanitize it again before storage using an allowlist (`p`, `br`, `h2`, `h3`, `strong`, `b`, `em`, `i`, `u`, `ul`, `ol`, `li`, `a`, and `blockquote`). Link URLs must only allow `http`, `https`, `mailto`, and `tel` protocols. Unsupported slugs should return `404`; invalid or visually empty title/content should return `400`.
